# Архитектурное оформление файлов и подсистем

Все файлы и модули, реализующие подсистемы ядра, должны содержать архитектурное описание в модульном docstring (`//!`) в начале файла.

## Структура модульного docstring:

1. **Название подсистемы** - первая строка после `//!`
2. **Краткое описание** - описание назначения подсистемы и её роли в ядре
3. **Раздел "# Архитектура"** - обязательный раздел, содержащий:
   - ASCII-диаграмму потока данных/вызовов в блоке кода с типом `text`
   - Диаграмма должна показывать взаимодействие компонентов, переходы между режимами (User/Kernel), потоки данных
   - Использовать символы для визуализации: `┌─┐│└┘`, `═`, `─`, `│`, `▼`, `▲` и т.д.
4. **Дополнительные разделы** - по необходимости добавлять разделы с описанием:
   - Соглашений о вызовах (calling conventions)
   - Структур данных и их назначения
   - Таблиц и их организации
   - Алгоритмов и особенностей реализации
5. **Раздел "# Отступления и упрощения"** - обязательный раздел, если реализация отличается от оригинальной Windows NT:
   - Перечисление всех отступлений от оригинальной реализации Windows NT
   - Упрощения, сделанные для текущей версии
   - Причины отступлений (требования Rust, временные ограничения, упрощение для начальной реализации)
   - Формат: маркированный список с описанием каждого отступления
   - Примеры: упрощённая проверка указателей, отсутствие поддержки некоторых функций, изменённая структура данных из-за требований Rust
   - **Важно:** формулировать как отступления от архитектуры Windows NT, а не от других реализаций
6. **Раздел "# TODO"** - опциональный раздел для перечисления текущих задач и ограничений:
   - Список незавершённых функций или упрощённых реализаций
   - Ограничения текущей реализации
   - Планируемые улучшения
   - Формат: маркированный список с описанием каждой задачи
7. **Источники** - в конце docstring указывать источники для анализа:
   - MSDN (для NT6.1 / Windows 7) - приоритетный источник
   - Версии Windows NT (например, NT6.1, NT5.1)
   - Пути к файлам в исходниках Windows (например, docs/ref/nt5src/XPSP1, docs/ref/nt5src/Win2K3)
   - Пути к файлам в исходниках ReactOS (например, docs/ref/reactos) - только как источник для анализа
   - Другие релевантные источники
   - **Важно:** ReactOS и другие реализации упоминаются только как источники в ссылках, не как основной ориентир соответствия

## Оформление кода внутри файла:

- Использовать разделители `// =============================================================================` для логического разделения секций кода
- Каждая структура, функция, константа должна иметь подробный docstring на русском языке
- В docstring функций указывать оригинальное имя функции Windows NT (если применимо)
- Комментарии должны объяснять логику работы, особенно неочевидные моменты

## Пример структуры:

````rust
//! Название подсистемы
//!
//! Краткое описание назначения и роли подсистемы.
//!
//! # Архитектура
//!
//! ```text
//! [ASCII-диаграмма потока данных/вызовов]
//! ```
//!
//! # Дополнительные разделы
//!
//! Описание соглашений, структур, алгоритмов...
//!
//! # Отступления и упрощения
//!
//! - ProbeForRead/ProbeForWrite - упрощённая реализация без полноценной fault-safe проверки
//!   (требуется поддержка обработки page fault в MM подсистеме)
//! - Поддержка аргументов 5+ в системных вызовах - пока не реализована
//!   (в оригинале аргументы передаются через стек, требуется извлечение из SYSCALL frame)
//!
//! # TODO
//!
//! - Упрощённая реализация ProbeForRead - требуется полноценная fault-safe проверка
//! - Поддержка аргументов 5+ в системных вызовах через стек
//!
//! Источники:
//! - MSDN (NT6.1 / Windows 7): ссылка/на/документацию (приоритетный источник)
//! - Windows NT 6.1: путь/к/файлу
//! - ReactOS: путь/к/файлу (источник для анализа)
````
