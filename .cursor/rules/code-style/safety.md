# Правила безопасности (Safety) для unsafe кода

## SAFETY комментарии

Каждый `unsafe` блок **обязательно** должен иметь комментарий `// SAFETY:`, объясняющий почему код внутри блока безопасен. Комментарий размещается непосредственно перед `unsafe` блоком.

### Формат

```rust
// SAFETY: [объяснение почему код безопасен]
unsafe {
    // код
}
```

### Что должен содержать SAFETY комментарий

- Объяснение почему инварианты безопасности соблюдены
- Ссылки на контракты/предусловия, если они гарантируют безопасность
- Описание проверок, выполненных ранее в коде

### Примеры

```rust
// SAFETY: указатель `ptr` проверен на null выше, размер буфера валидирован
unsafe { core::ptr::read(ptr) }

// SAFETY: мы единственный владелец данных, interrupts отключены
unsafe { GLOBAL_STATE.write(value) }

// SAFETY: halt loop — безопасен, не обращается к памяти
unsafe {
    asm!("cli", "hlt", options(noreturn));
}
```

## Документация unsafe функций

Все `unsafe fn` **обязательно** должны иметь секцию `# Safety` в документации, описывающую контракт который должен соблюдать вызывающий код.

### Формат

```rust
/// Описание функции.
///
/// # Safety
///
/// - Первое требование безопасности
/// - Второе требование безопасности
pub unsafe fn my_unsafe_function(...) { ... }
```

### Пример

```rust
/// Инициализирует NLS подсистему из данных LoaderBlock.
///
/// # Safety
///
/// - `lpb.UnicodeNlsBase` должен указывать на валидные NLS данные
/// - `lpb.UnicodeNlsSize` должен соответствовать реальному размеру данных
/// - Вызывается только один раз при старте ядра
pub unsafe fn rtl_initialize_nls_from_loader_block(
    lpb: &LOADER_PARAMETER_BLOCK,
) -> Result<(), NTSTATUS> { ... }
```

## unsafe в unsafe функциях

Даже внутри `unsafe fn`, каждый `unsafe` блок должен иметь `// SAFETY:` комментарий. Это делает явным какие именно операции требуют unsafe и почему они безопасны.

```rust
pub unsafe fn example() {
    // SAFETY: контракт функции гарантирует валидность указателя
    unsafe { *ptr = value; }
}
```

## Связь с документацией

- `# Safety` секция описывает **контракт** для вызывающего кода (что он должен гарантировать)
- `// SAFETY:` комментарий показывает **почему** конкретный unsafe код соблюдает контракт
