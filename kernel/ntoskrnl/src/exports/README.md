# NT PE-экспорты ядра (`ntoskrnl.exe`)

Этот модуль содержит **стабильные PE-экспорты** в стиле Windows NT (PascalCase, win64 ABI),
которые используются внешними модулями: `hal.dll`, boot-драйверы и прочие PE-компоненты.

## Архитектура

Экспорты формируют **внешний ABI-контракт** ядра `ntoskrnl.exe` для PE-import runtime.
Ошибка здесь ломает загрузку `hal.dll`/драйверов и совместимость в целом.

```
       (внешний PE модуль)
   hal.dll / driver.sys / bootvid.dll
                │   imports (IAT)
                ▼
    ┌──────────────────────────────┐
    │     ntoskrnl.exe exports     │  <── Этот модуль (exports/)
    │       KeBugCheckEx / ...     │
    │  ...                         │
    └───────────────┬──────────────┘
                    │ thin-wrapper (тонкая обёртка)
                    ▼
    ┌──────────────────────────────┐
    │    внутренние реализации     │  <── Подсистемы ядра (ke/, mm/, io/, ...)
    │ ke::bugcheck::ke_bug_check_ex│
    └──────────────────────────────┘
```

### Принцип разделения

| Слой               | Расположение             | ABI              | Именование                     | Назначение                        |
| ------------------ | ------------------------ | ---------------- | ------------------------------ | --------------------------------- |
| **Экспорты**       | `exports/`               | `extern "win64"` | PascalCase (`KeBugCheckEx`)    | Публичный контракт для PE-модулей |
| **Внутренние API** | `ke/`, `mm/`, `io/`, ... | Rust ABI         | snake_case (`ke_bug_check_ex`) | Реализация логики ядра            |

## Правила добавления экспортов

### Обязательные требования

1. **100% соответствие MSDN/WDK сигнатурам и поведению (NT 6.1 / Windows 7) — главный приоритет, любой ценой.**

2. **Никогда не "упрощаем" экспортируемую сигнатуру:**

   - не добавляем/убираем аргументы
   - не меняем типы
   - не меняем calling convention
   - не меняем возвращаемое значение

3. **Если функция пока не реализуема корректно:**

   - изменяем/добавляем внутренний API (snake_case) и подсистемы
   - **но НЕ меняем контракт экспорта**
   - уведомляем пользователя о необходимости изменить внутренний контракт

4. **Каждый экспорт обязан иметь:**

   - `extern "win64"` + `#[unsafe(export_name = "...")]`
   - Docstring на русском языке с оригинальным именем NT
   - **Ссылку на MSDN/WDK** на описание функции (приоритетный источник)

5. **Перед добавлением нового экспорта:**

   - Сверить точную сигнатуру/ABI/семантику по MSDN/WDK (NT 6.1 ориентир)
   - Убедиться, что в коде нет уже существующего экспорта с тем же NT-именем
   - Убедиться, что внутренняя реализация соответствует описанному поведению

6. **После добавления экспорта обновить `ntoskrnl.def`:**
   - Файл: `kernel/ntoskrnl/ntoskrnl.def`
   - Добавить имя функции в соответствующую секцию (Ke*, Mm*, Io\*, и т.д.)
   - **Использовать ordinal из референсной секции** (закомментированные экспорты Windows 7 в конце файла)
   - Это необходимо для генерации import library (`ntoskrnl.lib`) через `llvm-dlltool`
   - Без обновления `.def` файла экспорт не будет доступен для линковки внешних модулей

## Файл определений экспортов (`ntoskrnl.def`)

Файл `kernel/ntoskrnl/ntoskrnl.def` определяет публичный API ядра для PE-импорта.

### Назначение

- Генерация import library (`ntoskrnl.lib`) через `llvm-dlltool`
- Документирование экспортируемых символов
- Контроль порядка экспортов (ordinals)

### Формат записей

```def
; Комментарий
ИмяФункции                    ; без ordinal
ИмяФункции @ordinal           ; с явным ordinal
ИмяФункции @ordinal NONAME    ; экспорт только по ordinal
```

### Референсная секция Windows 7

В конце файла `ntoskrnl.def` находится закомментированная секция с полным списком
экспортов оригинального ядра Windows NT 6.1 (Windows 7) с их ordinals:

```def
; >>> AUTOGENERATED: WIN7 EXPORTS BEGIN
; ...
; KeBugCheck @712
; KeCancelTimer @714
; ...
; <<< AUTOGENERATED: WIN7 EXPORTS END
```

**При добавлении нового экспорта необходимо:**

1. Найти функцию в референсной секции
2. Использовать указанный там ordinal для совместимости с оригинальным ABI

### Синхронизация с кодом

**ВАЖНО:** При добавлении нового экспорта в `exports/*.rs` необходимо также добавить
соответствующую запись в `ntoskrnl.def`. Без этого:

- Экспорт будет присутствовать в бинарнике, но не в import library
- Внешние модули (`hal.dll`, драйверы) не смогут слинковаться с этим экспортом

### Пример добавления

```def
; =========================================================================
; Kernel Executive (Ke*)
; =========================================================================

; KeBugCheckEx - критическая ошибка (BSOD)
; https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/nf-wdm-kebugcheckex
KeBugCheckEx @713
```

Ordinal `@713` взят из референсной секции Windows 7 экспортов в конце файла.

## Структура модуля

Экспорты разбиты по подсистемам ядра (соответствует NT naming conventions):

| Модуль   | Префикс | Подсистема             | Статус      |
| -------- | ------- | ---------------------- | ----------- |
| `ke.rs`  | `Ke*`   | Kernel Executive       | Активен     |
| `mm.rs`  | `Mm*`   | Memory Manager         | Активен     |
| `ex.rs`  | `Ex*`   | Executive              | Планируется |
| `ps.rs`  | `Ps*`   | Process/Thread Manager | Планируется |
| `io.rs`  | `Io*`   | I/O Manager            | Планируется |
| `ob.rs`  | `Ob*`   | Object Manager         | Планируется |
| `rtl.rs` | `Rtl*`  | Runtime Library        | Планируется |
| `hal.rs` | `Hal*`  | HAL exports из ядра    | Планируется |

## Макросы для экспортов

Модуль предоставляет два макроса для объявления thin-wrapper экспортов:

### `nt_export_fn!` — для safe функций

```rust
nt_export_fn!(
    "KeBugCheckEx" => KeBugCheckEx(
        bug_check_code: u32,
        bug_check_parameter1: ULONG_PTR,
        bug_check_parameter2: ULONG_PTR,
        bug_check_parameter3: ULONG_PTR,
        bug_check_parameter4: ULONG_PTR,
    ) -> ! = ntoskrnl::ke::bugcheck::ke_bug_check_ex
);
```

### `nt_export_unsafe_fn!` — для unsafe функций

```rust
nt_export_unsafe_fn!(
    "MmMapIoSpace" => MmMapIoSpace(
        physical_address: PHYSICAL_ADDRESS,
        number_of_bytes: SIZE_T,
        cache_type: MEMORY_CACHING_TYPE,
    ) -> PVOID = ntoskrnl::mm::mmio::mm_map_io_space
);
```

### Генерируемый код

Макросы генерируют:

```rust
#[unsafe(export_name = "KeBugCheckEx")]
pub extern "win64" fn KeBugCheckEx(...) -> ... {
    внутренняя_функция(...)
}
```

## Примеры

### Добавление нового экспорта

1. Найти документацию на MSDN/WDK:

   - Например: https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/nf-wdm-kebugcheckex

2. Определить точную сигнатуру:

   ```c
   // MSDN сигнатура
   void KeBugCheckEx(
     ULONG     BugCheckCode,
     ULONG_PTR BugCheckParameter1,
     ULONG_PTR BugCheckParameter2,
     ULONG_PTR BugCheckParameter3,
     ULONG_PTR BugCheckParameter4
   );
   ```

3. Реализовать внутреннюю функцию в соответствующей подсистеме:

   ```rust
   // ke/bugcheck.rs
   pub fn ke_bug_check_ex(
       bug_check_code: u32,
       p1: ULONG_PTR, p2: ULONG_PTR, p3: ULONG_PTR, p4: ULONG_PTR,
   ) -> ! {
       // реализация
   }
   ```

4. Добавить экспорт в соответствующий файл `exports/`:

   ```rust
   // exports/ke.rs

   /// KeBugCheckEx
   ///
   /// Вызывает критическую ошибку (bugcheck/BSOD) с указанными параметрами.
   /// Функция не возвращает управление.
   ///
   /// MSDN: https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/nf-wdm-kebugcheckex
   nt_export_fn!(
       "KeBugCheckEx" => KeBugCheckEx(
           bug_check_code: u32,
           bug_check_parameter1: ULONG_PTR,
           bug_check_parameter2: ULONG_PTR,
           bug_check_parameter3: ULONG_PTR,
           bug_check_parameter4: ULONG_PTR,
       ) -> ! = ntoskrnl::ke::bugcheck::ke_bug_check_ex
   );
   ```

5. Обновить файл `ntoskrnl.def`:

   ```def
   ; kernel/ntoskrnl/ntoskrnl.def

   ; =========================================================================
   ; Kernel Executive (Ke*)
   ; =========================================================================

   ; KeBugCheckEx - критическая ошибка (BSOD)
   ; https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/nf-wdm-kebugcheckex
   KeBugCheckEx @713
   ```

   - Ordinal `@713` взят из референсной секции Windows 7 в конце `ntoskrnl.def`
   - Без этого шага экспорт не попадёт в `ntoskrnl.lib` и внешние модули не смогут
     использовать эту функцию
